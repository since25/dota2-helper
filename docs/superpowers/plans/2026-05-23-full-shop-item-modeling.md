# 全部商店物品建模计划

## 目标

一次性覆盖当前 `dotaconstants.items` 中可购买的全部商店物品，并把普通物品、阿哈利姆神杖、阿哈利姆魔晶接入伤害计算、英雄模型上下文和前端查看页。中立物品本阶段不处理。

## 中间检查关卡

### 关卡 1：物品范围确认

产物：

- `npm run items:scope`
- `audit-runs/item-scope-latest/index.html`
- `audit-runs/item-scope-latest/items.json`
- `audit-runs/item-scope-latest/summary.json`

确认内容：

- 哪些条目属于候选商店物品。
- 哪些条目因为配方、无名称、无价格、未知分类被排除。
- 哪些条目需要人工确认，例如 Roshan 掉落版本、Cheese、Courier、过时但仍在本地数据中的物品。

通过标准：

- 用户确认候选范围和 review 项处理规则。

### 关卡 2：物品语义层

产物：

- `itemModels/schema.js`
- `itemModels/registry.js`
- `itemModels/autoModels.js`
- `itemModels/items/*.js` 只用于人工覆盖需要特别处理的物品。
- 语义分类覆盖所有关卡 1 确认纳入的商店物品。

分类：

- 直接伤害：达贡、血腥榴弹、辉耀、希瓦等。
- 持续伤害：辉耀、血腥榴弹等。
- 护甲/魔抗/伤害增幅：黯灭、强袭、纷争、虚灵、法师克星等。
- 攻击触发：标枪、漩涡、雷锤、金箍棒、碎颅锤等。
- 属性与面板：力量、敏捷、智力、攻击力、攻速、生命、魔法、护甲等。
- 条件/非伤害：位移、驱散、控制、保命、反隐、回蓝回血等。
- 神杖/魔晶：价格和基础属性作为物品，英雄专属技能变化作为条件升级。

通过标准：

- 每个纳入物品至少有一个明确语义分类。
- 非伤害数值不会进入 Unknown damage。
- 所有 `review` 和 `unsupported` 项必须带原因。

### 关卡 3：API 和前端查看页

产物：

- 新增或扩展物品 API。
- 物品列表可读页。
- 单物品模型可读页。
- 英雄伤害模型页显示神杖/魔晶相关条件。

通过标准：

- 用户能在浏览器中查看全部商店物品语义。
- 原始 JSON 仍保留，便于审计。

### 关卡 4：伤害计算器接入

产物：

- 计算器支持选择物品。
- 支持手动输入触发次数、作用时间、敌方护甲/魔抗、目标生命等运行时参数。
- 物品的护甲削减、魔抗变化、伤害增幅会参与最终伤害估算。

通过标准：

- 典型样例通过：黯灭、强袭、纷争、虚灵、达贡、辉耀、刃甲、血棘、标枪/漩涡系、魔晶、神杖。

### 关卡 5：LLM 上下文接入

产物：

- prompt 中加入结构化物品语义。
- 明确区分固定伤害、理论伤害、条件伤害、非伤害修正。

通过标准：

- LLM 不再把物品移动速度、护甲、价格等误当成未知伤害。
- LLM 能说明魔晶/神杖收益和条件，而不是把它们默认计入基础爆发。

## 当前第一关过滤规则

候选规则：

- 有 `dname`。
- `cost > 0`。
- 不是 `recipe_*`，名称也不包含 Recipe。
- `qual` 属于 `component`、`secret_shop`、`consumable`、`consumable;laning`、`common`、`rare`、`epic`、`artifact`。

需要人工确认：

- Roshan 专属版本。
- Cheese 和 Block of Cheese。
- Courier 相关条目。
- 本地数据仍保留但当前版本可能不可购买的旧物品。

排除规则：

- recipe 条目。
- 无名称条目。
- 无价格或价格小于等于 0 的条目。
- 未知 quality 且无法证明属于商店的条目。
